# SlickTrace — the frontend

One product, two surfaces, over the SAR + AIS oil-spill attribution system.

Project-wide documentation lives at the repository root and is not duplicated
here: [`../CLAUDE.md`](../CLAUDE.md) for operating rules,
[`../ISSUES.md`](../ISSUES.md) §6 for open frontend defects,

## Run

```bash
npm install
```

```bash
npm run dev
```

Port 5180. `http://127.0.0.1:5180/#/console` is the operations console.

```bash
npm run build
```

Runs `tsc -b` then the production Vite build. There is no test harness here yet.

## The two surfaces

| Surface | Route | What it is |
|---|---|---|
| **Home** | `#/` | A scroll page narrating what happened: detection, drift and its forcing, forecast, root cause, suspects, method |
| **Console** | `#/console` | An operations workstation — map, dockable panels, a shared timeline — with the same panels repeated below the fold at a readable width |

It began as four independent design studies. Signal contributed the home page's
composition and typography; Dossier the charts and plates; Orbit the live
readouts; Terminal became the console and then grew a window manager. Both the
plate and instrument files were already fully token-driven, which is what made
the recombination a merge rather than a rewrite.

## Layout

```
src/
  sim/            the simulation: drift, field, ais, scoring, scenarios
  map/            MapCanvas, basemap layers, ParticleOverlay
  lib/
    playback.ts   the event hour by hour: phase, extent, contacts, checkpoints
    format.ts     vocabulary: term labels, timestamps, ageStatement()
    palette.tsx   the runtime colour overlay, both surfaces
    project.ts    SVG projection arithmetic for figures
    motion.ts     anime.js scope + scroll reveal
    spill.ts      per-block scenario state
    hash.ts       hash routing
  components/     shared: FloatShell, PalettePanel, SarTile
  content.ts      the project's facts, not its copy
  theme.ts        map paint, fonts, accents for both surfaces
  site/           home page: SiteShell, Nav, sections/, plates, instruments
  console/        console: ConsoleShell, Workspace, Timeline, panes, dock/
```

## Invariants worth knowing before editing

**Every figure owns its own spill.** Each data block on the home page carries
its own spill control, and changing one must not change any other. `useSpill`
is one instance per block with its own run, clock and selection. `buildRun` is
memoised per `scenario:variant`, and a block does not build its run until it
nears the viewport.

**The console is a window manager.** Panels tear off, float, resize and dock
again. Landing position is *canonical, never positional* — panel 03 always
lands between 02 and 04, closing over absent panels.

**`createScope` confines and reverts.** anime.js v4 scopes are what stop five
mount/unmount cycles leaking timers into each other. The scroll-reveal option
is `repeat: false`; `once: true` is silently ignored in v4.

**Nothing here is measured.** All content is generated by `src/sim/` in the
browser. Locations, scale, forcing, AIS and timings are simulated and the
console says so — the `SIM` badges and the `provenance` fields are load-bearing,
not decoration. Do not present any of it as a measured result or as the output
of a trained model.

**`.backup/2026-08-31-animation/` is excluded from Tailwind** via
`@source not "../.backup"` in `index.css`. Without that exclusion Tailwind v4
scans it and dead components there still emit utilities into the shipped CSS.
The snapshot itself predates the recombination and can no longer be restored
cleanly — it references `src/design.ts` and `src/components/DesignSwitcher.tsx`,
neither of which still exists.

## Not yet true

The frontend is not wired to the backend; `PLAN/INTERFACES.md` §3 defines the
transport and `backend/app/` is still empty. Upload currently fingerprints
against six supplied sample images and plays a scripted sequence. The hindcast
shown before T0 is a presentation transform, not physics.
